1 一句话结论

先纠正一个混淆：这个项目没有「固件」要上传。DAYU200 的系统镜像由厂商提供，你的部署指南第一句就写了「无需烧录系统镜像」；你实际做的是把编译签名好的 .hap 应用包用 hdc install 安装到板子，相当于往手机装 APP。

所以按你问的两种形式，答案是「分三类，不是二选一」：

东西放哪理由
源码与文档：ArkTS 代码、build-profile.json5、安装脚本（脱敏后）、部署指南、上板实录Git 仓库（源码形式）文本、小、需要版本历史，别人要能看懂并自己构建
自己生成的成品：*.hap 应用包Release 附件（可选，本项目建议不发）二进制、可重新生成、不进 Git 历史；但见下面两个致命限制
第三方大件：hdc.exe、hap-sign-tool.jar、DevEco / SDK、系统镜像 *.img不上传，README 只写官方下载方式不是你的作品、体积大（jar 就 12.35 MB）、有许可与版本匹配问题
私钥与凭据：*.p12、绑定 UDID 的 debug profile、真实配置文件、含密钥的完整包 zip任何形式都不上传泄露凭据 / 别人也用不了
本项目的两个致命限制，决定了「发 HAP」意义不大：
① 签名 HAP 用的 debug profile 里带 device-id（绑定你这块板子的 UDID），别人拿去装会报 9568322 not trusted app source；
② carfleet-oh-signed.hap 在板子上安装成功但启动崩溃（HarmonyOS 6 / API 22 字节码 vs 板子实测 API 15 运行时不兼容）。发出去等于发一个跑不起来的成品。
因此推荐做法：三个仓库只放源码 + 文档 + 脱敏脚本，不建 Release 附件；在 V3 的 README 里写清楚「上板复现」五步（第 ⑤ 节给了可复制的示范段落）。

2 生活比喻：装修、搬家具，和一本菜谱

先分清「刷系统」和「装应用」

真正的烧录（刷系统）你这个项目做的（装应用）
比喻给房子重新铺水电、换整套管路往已经装好的房子里搬一件家具
产物系统镜像 *.img（几百 MB ~ 几 GB）应用包 *.hap（本项目 321 KB / 370 KB）
工具厂商烧录工具、DevEco Device Tool、USB 驱动hdc install（DevEco SDK 自带命令行）
写进哪里板子的 Flash / 系统分区，覆盖整个系统板子的应用沙箱，随时可卸载
本项目是否涉及否 —— 板子系统是预装的，本机也没有镜像是 —— 上板实录就是 hdc install -r

部署指南原文：「板子系统已是 OpenHarmony……无需烧录系统镜像，只需把编译签名好的 HAP 应用安装上去（相当于往手机装 APP）」。所以「烧录的固件」在你这里其实指的就是 HAP 应用包，「烧录工具」其实是 hdc。名字叫错了，但分类方法不变。

再说仓库 / Release / 链接的区别

比喻对应特点
菜谱（每一步怎么写、改了哪一勺盐）Git 仓库里的源码文本、能逐行比较、每次改动都留痕
做好的一份菜（打包好直接能吃）Release 附件里的成品对应某个版本号，能单独下载 / 换掉 / 删除，不进代码历史
厨房设备（灶台、烤箱，厂家生产）SDK / hdc / 签名 jar / 系统镜像不是你做的，说明书里写「去哪买、什么型号」就够了
自家钥匙签名私钥 .p12、debug profile给出去就等于开门迎客，而且别人拿到也配不上自家的锁
为什么 Git 不适合塞二进制成品？Git 会把每个版本的文件完整存一份。你每改一行 ArkTS 就重新打包一次 370 KB 的 HAP，提交十次历史里就有十份几乎一样的二进制，clone 越来越慢，而且二进制没法 diff（看不出改了什么）。Release 附件是「挂在版本号上的成品」，跟代码历史分开，正好补这个短板。

3 在四层架构里的位置

回想运行时四层：设备层（车）→ 云端层（IoTDA）→ 业务后端层（Flask 8000）→ 客户端层（网页 / APP）。

  • HAP 应用包 = 客户端层 APP 的「可安装形态」。源码 Index.ets 编译打包后变成 HAP，装到板子上才成为能点的界面。
  • 板子系统镜像 = 客户端层设备「开机前的底座」，在四层启动之前，不属于业务链路。
  • hdc = PC 与设备之间临时的调试通道（USB / TCP），只在安装、抓日志时用；小车跑起来后的业务数据走 HTTP / MQTT / WebSocket，跟 hdc 无关。
  • 签名工具与证书 = 开发交付层的「盖章流程」，产出 HAP 之前用一次，运行时完全不参与。
  • GitHub 仓库 / Release = 交付层，上一份教程讲过：断网、删仓库，四层照常能跑。

如果决定发 Release 附件：具体怎么做

  1. 本地算出校验值，方便别人验证下载没坏：
cd E:\Harmony\Project\CarFleet\entry\build\default\outputs\default
Get-FileHash -Algorithm SHA256 .\carfleet-oh-unsigned.hap
  1. 仓库网页 → Releases → Create a new release → 新建 tag，例如 v0.1-onboard-experimental
  2. 标题 / 说明里写清楚：适用 SDK 版本、板子系统版本、已知启动崩溃问题、SHA256、以及「签名版绑定特定 UDID，别人装不上」
  3. 拖入 unsigned HAP（未签名的那个，别人可用 DevEco 自动签名自己签），或干脆只放一份构建说明
  4. 点 Publish release；回到 README 加一句「可安装成品见 Releases 页面」
Release 附件 ≠ 保险箱。公开仓库的 Release 附件同样是公开的，而且一旦被人下载/缓存，删掉也收不回。所以 *.p12、含真实密钥的配置文件、以及 E:\Harmony\CompleteProject\V3-Fleet-Complete.zip（20 MB 完整包）绝不能当附件传。上一轮整理时划的红线，在这里同样成立。

## 在 DAYU200 开发板上复现（可选）

本仓库只提供源码，不提供系统镜像、SDK 与已签名应用包：

1. 板子系统由厂商镜像提供，请按开发板官方文档获取对应版本；本项目**不需要刷机**。
2. 安装 DevEco Studio 及与板子系统匹配的 OpenHarmony SDK，把 `sdk/.../toolchains` 加入 PATH 以使用 `hdc`。
3. 用 DevEco 打开 `app/`，使用**自动签名**生成自己的调试证书与 profile（本仓库不含私钥）。
4. 构建得到未签名 HAP 后签名，再执行 `hdc -t <设备序列号> install -r <你的HAP>`。
5. 详细步骤与已知问题见 `docs/V3-学-把软件装到DAYU200开发板.html`、`docs/V3-学-CarFleet上板实录.html`。

> 已知限制：现有 HAP 为 HarmonyOS 6 / API 22 字节码，在实测 API 15 的板子上安装后启动崩溃，
> 需要用匹配板子的 SDK 重新编译。签名版 HAP 绑定特定设备 UDID，不可跨板使用。
为什么这个方案最稳：别人拿到的是「能自己构建、能看懂」的源码，而不是一个绑死你硬件、还跑不起来的二进制；同时你完全绕开了私钥、许可证、大文件、仓库膨胀这四个麻烦。

把「装 HAP」当「烧录固件」，以为仓库里缺了系统镜像到处找不存在的 .img，白忙一场看部署指南第一句：无需刷系统，只需 hdc install

9 自测小问题（点开看答案）

1. 这个项目上板，需要上传「烧录固件」吗？

不需要，而且项目里也没有。板子系统是预装的，部署指南明确写「无需烧录系统镜像」；你做的是 hdc install 安装 .hap 应用包，等于往手机装 APP。真正的系统镜像由厂商提供，本机也没存。

2. hap-sign-tool.jar 和 hdc.exe 该以什么形式发布？

都不该由你发布。它们是 DevEco / OpenHarmony SDK 自带的第三方工具（jar 就有 12.35 MB），放在仓库里会白白增大体积、还涉及再分发许可。README 里写清楚「装哪个版本 SDK、工具在 toolchains/ 下、怎么加 PATH」即可。

3. 为什么不把 *.hap 直接 commit 进 Git 仓库？

二进制每重新打包一次，Git 历史就多存一份完整副本，且没法 diff；clone 会越来越慢。当前 .gitignore 已排除 *.hap，复检脚本也会把它判为「不该上传的文件」。成品应该挂在某个版本号的 Release 附件上，与代码历史分离。

4. Release 附件是不是就安全了？私钥能不能放进去？

不能。公开仓库的 Release 附件同样是公开的，下载/缓存之后删掉也收不回。*.p12 私钥、含真实密钥的配置文件、以及含密钥的 V3-Fleet-Complete.zip 完整包，任何位置都不能上传。

5. 为什么签名好的 HAP 发给别人也装不上？

它用的是 debug 类型的 profile，里面带 device-id，绑定你这台 DAYU200 的 UDID。换一台板子签名校验不通过，会报 9568322 not trusted app source。要给别人用，得给未签名包 + 让他用 DevEco 自动签名，或直接给源码自己构建。

6. 就算别人装上了 carfleet-oh-signed.hap，为什么还是看不到界面？

因为它是 HarmonyOS 6 / API 22 的字节码，板子实测运行时是 API 15，安装能成功但启动崩溃（上板实录里的 Cpp Crash / stub 未加载）。所以发布这个成品意义不大，必须在说明里如实标注已知限制，或用匹配板子的 SDK 重新编译。

7. 综合下来，最推荐的做法是什么？
