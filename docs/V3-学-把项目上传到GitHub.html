1 一句话结论

每个版本目录各建一个 GitHub 仓库，顺序永远是：git init → git add → git status 肉眼核对 → git commit → 网页建空仓库 → git remote add → git push -u origin main；三个目录重复三遍。

换句话说：先在本机打包存档，再在 GitHub 上准备一个空柜子，最后把存档推上去。顺序反了（先建仓库并勾了 README）就会撞车。

本教程只讲操作，不会替你执行 git init / push。所有命令都按你这台机器的真实路径写好了，把 <你的用户名> 换成 GitHub 账号名即可。

2 生活比喻：给三个版本各寄一个快递

现实动作Git 里的动作命令
桌上一堆散的材料（工作区）你正在编辑的文件，Git 还没管—
挑出要寄的、装进纸箱（暂存区）登记「这次要提交哪些文件」git add .
封箱、贴单、写「第 1 箱」（本地仓库）生成一次永久存档，本机留底git commit -m "..."
先在快递站租一个空柜子（远程仓库）在 GitHub 网页上新建一个空仓库网页点击
填收件地址把本地仓库和远程地址绑定git remote add origin ...
把箱子送过去把存档上传到 GitHubgit push -u origin main
关键理解：git add 和 git commit 都只发生在你自己电脑上，这时候文件还没上网，改错还来得及；只有 git push 才是真正「公开」的那一步。所以核对工作一定要放在 commit 之前、push 之前。

三个版本 = 三个独立纸箱、三个独立柜子。不要图省事把整个 GitHub-Ready 当成一个仓库推 —— 那样三个 README 会互相打架，别人也看不清哪代是哪代。

3 在项目里的位置：它不属于「四层架构」

我们之前讲的四层是小车跑起来时的分工：设备层（车）→ 云端层（IoTDA）→ 业务后端层（Flask 8000）→ 客户端层（网页 / APP）。

GitHub 不在这四层里。它属于「开发流程 / 交付层」：小车运行时完全不依赖 GitHub；断网、删掉 GitHub 仓库，三端照常能跑。它只负责三件事：给代码留历史存档、让别人能 clone、给答辩 / 作品集一个可访问的链接。

安全自检：确认「只推这三个目录」

打开 PowerShell（开始菜单搜 PowerShell 即可），先在任意位置跑一次复检脚本。它用自身所在目录定位，所以不用 cd 也能跑：

python E:\Harmony\GitHub-Ready\verify_before_push.py
预期：列出三行文件数统计，最后一行 [PASS] 未发现真实凭据、本机路径或不应上传的产物；必备文件齐全。
若出现 [FAIL]：先按提示修掉再往下走，别跳过。脚本会告诉你具体是哪个文件第几行命中了哪条规则。

再确认一次：本教程所有 cd 都指向 E:\Harmony\GitHub-Ready\<版本目录>，没有别的路径。

1

确认 Git 与提交身份（本机已完成，可跳过）

git --version
git config --global --get user.name
git config --global --get user.email
预期：三行都有输出。本机实测 git version 2.55.0.windows.3，用户名和邮箱都已配置。
若后两行为空：执行下面两行（换成你自己的名字和 GitHub 注册邮箱）；这只是给提交签名，不影响功能。
git config --global user.name "你的名字"
git config --global user.email "你的GitHub邮箱"

PowerShell 里中文 commit message 一般没问题；若出现乱码，把 -m 内容换成英文即可。

2

登录 GitHub，选一种认证方式

打开 https://github.com 登录（没有账号先注册，邮箱验证一下）。2021 年 8 月起，HTTPS 推送不再接受账号密码，必须二选一：

方式 A · HTTPS + Token（推荐新手，第 7 步照这个走）

  1. 右上角头像 → Settings → 左侧菜单拉到最底 → Developer settings
  2. Personal access tokens → Tokens (classic) → Generate new token (classic)
  3. Note 填 upload-car-project；Expiration 选 90 天；只勾选 repo
  4. 点 Generate token，立刻复制那串 ghp_...（页面刷新后就再也看不到了，先粘到记事本暂存）
Token 等同于账号密码：别写进任何文件、别贴进代码、别发给别人。它只在第 7 步弹窗时当「密码」粘贴一次，Windows 会替你记住。

方式 B · SSH 密钥（备选，配置一次以后不用再输）

ssh-keygen -t ed25519 -C "你的GitHub邮箱"
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | Set-Clipboard
ssh -T git@github.com

第一条一路回车（不要设密码短语也可）；第二条把公钥复制到剪贴板；然后 GitHub → 头像 → Settings → SSH and GPG keys → New SSH key → 粘贴 → Add SSH key。第三条看到 Hi <用户名>! You've successfully authenticated 即成功。此时远程地址要用 git@github.com:<用户名>/<仓库>.git。

本机 C:\Users\HP\.ssh\ 已有一对 RSA 密钥，也可以直接把 id_rsa.pub 的内容贴到 GitHub；但 ed25519 更省心，不冲突。

3

在 GitHub 网页上新建「空」仓库

  1. 右上角 + → New repository
  2. Owner 选你自己；Repository name 填 smart-car-v1-tcp
  3. 选 Public（想给答辩老师看）或 Private（只自己看）
  4. 「Initialize this repository with」下面三项一个都不要勾：不要 Add a README file、不要 Add .gitignore、不要 Choose a license
  5. 点 Create repository，复制页面上那串 HTTPS 地址：https://github.com/<你的用户名>/smart-car-v1-tcp.git
为什么必须空？本地已经有 README 和 .gitignore。远程若自带一个初始提交，两边历史对不上，push 会被拒绝（non-fast-forward）。真碰上了用 git pull --rebase origin main 后再 push，但对新手最省事的办法是「删掉重建一个空仓库」。

先只建 V1 这一个，走完第 4~7 步再回头建另外两个 —— 一次只盯一个仓库，不容易串。

4

本地建仓 + 暂存 + 肉眼核对（最关键的一步）

cd E:\Harmony\GitHub-Ready\01-TCP-V1
git init
git add .
git status --short
git ls-files | Select-String -Pattern 'ai_config.json|cloud_config.json|devices.json|\.hap|\.p12|\.db'
预期：git init 提示 Initialized empty Git repository in .../01-TCP-V1/.git/；git status --short 列出约 63 行 A ...（A = 新增待提交）；最后一条命令没有任何输出，说明敏感文件确实没进清单。
若最后一条有输出：说明某个不该上传的文件被加进来了。用 git restore --staged 文件名 把它移出暂存区，再补进 .gitignore，然后重新 git status --short。

肉眼核对清单：逐行扫一眼 git status --short，确认没有 .hap / .p12 / .db / .log / __pycache__ / build/ / 真实的 ai_config.json 等。这一步只要 10 秒，但能挡住 99% 的事故。

5

提交快照（只在本机，还没上网）

git commit -m "feat: V1 TCP 直连单车版（脱敏整理）"
git show --stat --oneline HEAD
预期：第一条输出 [main (root-commit) xxxxxxx] ... 63 files changed（文件数按实际略有出入）；第二条列出本次提交的文件名清单，可以再复核一次。
若提示 Author identity unknown：回到第 1 步配置用户名邮箱。若提示中文乱码：把 message 换成英文，例如 feat: V1 tcp car (sanitized)。
到这一步为止，所有东西还在你硬盘上。发现错了可以用 git reset --soft HEAD~1 撤销这次提交（文件不会丢），重做即可。
6

绑定远程地址

git branch -M main
git remote add origin https://github.com/<你的用户名>/smart-car-v1-tcp.git
git remote -v
预期：git remote -v 显示两行，origin 后面跟着你刚复制的地址，且仓库名是 v1-tcp。
若提示 remote origin already exists：用 git remote set-url origin 新地址 改，不用删了重建。若走 SSH：地址换成 git@github.com:<用户名>/smart-car-v1-tcp.git。
7

推送（真正上网的那一步）

git push -u origin main

第一次会弹认证窗口：用户名填 GitHub 账号名，密码框粘贴第 2 步生成的 ghp_... Token（不是账号密码）。走 SSH 方式则不会弹窗。

预期：出现 Enumerating objects... / Writing objects... / To https://github.com/... / * [new branch] main -> main，最后提示 branch 'main' set up to track 'origin/main'。
认证失败：Windows 可能记住了旧密码。打开「控制面板 → 凭据管理器 → Windows 凭据」，删掉 git:https://github.com 再重试。
连不上 / 超时：见第 ⑦ 节的网络坑。
被拒绝（rejected / non-fast-forward）：多半是第 3 步勾了 README，删掉远程空仓库重建，或本地执行 git pull --rebase origin main 后再 push。
-u 的意思是「记住这个上游」，以后改完代码只要 git add . → git commit -m "..." → git push 三步即可，不用再带 origin main。

6 上传后验收（在网页上做，别敲命令）

  • 刷新仓库页面，能看到 README.md 被渲染成首页说明，标题和目录表格正常显示。
  • 文件数对得上：V1 约 63 个、V2 约 61 个、V3 约 88 个（页面显示的是「文件条目」，略有出入正常）。
  • 用 GitHub 页面顶部的搜索框（或按 t 键跳文件搜索）搜 ai_config.json / devices.json / cloud_config.json / .hap —— 应该一个都搜不到；能搜到的必须只有 *.example.json。
  • V2 打开 backend/cloud_backend.py，目视确认 AK/SK 处是 os.environ.get(...) 和 YOUR_... 占位符。
  • V3 打开 setup.py 和 .gitignore，确认本地生成配置的流程说明还在。
  • 点 Commits，应只有 1 条提交（root-commit），说明是干净的首次上传。

9 自测小问题（点开看答案）

1. 执行完 git add . 后，文件已经上传到 GitHub 了吗？

没有。git add 只是把文件登记进「暂存区」（装进纸箱），还在本机。commit 也只是本机存档，只有 push 才上网。所以核对机会有三次。

2. 新建仓库时手滑勾了「Add a README file」，push 会怎样？为什么？

会被拒绝（non-fast-forward）。因为远程凭空多了一个本地没有的初始提交，两条历史对不上。最简单是删掉重建一个空仓库；或者先 git pull --rebase origin main 把远程那条接在本地历史前面，再 push。

3. push 弹窗要密码，该填什么？

用户名填 GitHub 账号名；密码框粘贴第 2 步生成的 ghp_... Personal Access Token（classic，勾了 repo）。账号登录密码早就被 GitHub 禁用于 Git 推送了。走 SSH 方式则不弹窗。

4. 为什么绝对不能在 E:\Harmony\CompleteProject\ 里 git add .？

那里有含真实密钥的完整包 zip、原始配置文件和本机签名资料，是上一轮「本地存档包」而非「待公开仓库」。公开仓库会被自动爬取，密钥泄露后要先轮换凭据、再清历史，代价很大。要公开只推 GitHub-Ready 下三个目录。

5. git push -u origin main 里的 -u 有什么用？

把本地 main 与远程 origin/main 绑定为「上游」，以后直接 git push 就行。不加也能推，只是每次都要写全。

6. 同学在另一台电脑 clone 了 V3，为什么还得跑 python setup.py？

因为真实的 ai_config.json / cloud_config.json / devices.json 按设计不入库（.gitignore 忽略），仓库里只有 *.example.json 模板。setup.py 用模板生成他自己的本地配置。V2 同理，要用 set_env.example.bat 里的清单设环境变量。

7. 如果真把密钥 push 上去了，第一件事该做什么？

先去各个平台轮换 / 作废密钥（华为云 AK/SK、设备密钥、模型 API Key），再去处理 Git 历史。因为公开仓库会被爬虫立刻抓取，「删掉文件」救不回已经泄露的凭据。
