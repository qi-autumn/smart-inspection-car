2生活比喻：一个箱子，三本相册，三张标签

上一版「三个仓库」相当于寄三个快递：三个箱子、三张单、三次签收，还容易把地址贴串。你现在选的单仓库是：

  • 一个箱子＝ 一个 Git 仓库，里面放三本相册（01-TCP-V1 / 02-Cloud-V2 / 03-Fleet-V3）。
  • 一次寄出＝ 一次 git push，别人 clone 一次就全拿到。
  • 三张标签＝ v1.0.0 / v2.0.0 / v3.0.0 三个 tag，贴在箱子历史的三个时间点上，方便别人「只看 V1 那一版」。
  • 随箱附赠的样品＝ Release 附件。样品不放进箱子本体（不进 Git 历史），单独挂在标签旁边，谁想要谁下载。

关键差别：仓库只有一条 Releases 列表，所以三个版本的附件必须靠命名前缀区分，不能只叫 source.zip。

3在项目里的位置：它不属于运行时的四层架构

推送（真正把东西送出去的那一步）

PowerShell
git push -u origin main
SSH 预期：不弹任何账号密码框，直接出现 Enumerating objects ... Writing objects ... To github.com:qi-autumn/smart-inspection-car.git * [new branch] main -> main。
HTTPS 预期：可能弹出 Git Credential Manager 窗口；用户名填 qi-autumn，密码框不能填账号密码（2021 年起已禁用），要用 Personal Access Token。本机凭据管理器里已有可用凭据，通常会自动带上。

熟悉流程的小技巧：push 完紧接着敲 git status，会看到 Your branch is up to date with 'origin/main' —— 这句话就是「本地与远端已同步」的凭证。

9自测小问题（点开看答案）

① 为什么 SSH 认证成功了，还得去网页手动建仓库？

SSH 只负责「证明你是谁」，GitHub 不提供用 SSH 创建仓库的接口。创建仓库是账号级操作，必须在网页（或调用带 Token 的 API）完成。

② git push -u origin main 里的 -u 有什么用？

把本地 main 和远端 origin/main 建立上游关联。之后第二次推送只写 git push 就行，不用再写分支名。

③ 打了 tag 就能在网页 Releases 里选到吗？

不能，还得 git push origin --tags。git push 默认只推分支。

④ 三个版本放在一个仓库，为什么附件名还要加前缀？

因为一个仓库只有一条 Releases 列表，附件都平铺在同一处。不加 v1-/v2-/v3-，下载的人分不清哪个对应哪一代。

⑤ 源码快照 zip 为什么不放进 Git 仓库？

它是可由源码重新生成的二进制产物，进 Git 会让每次改动都多存一份全量副本、历史膨胀。Release 附件正是为「成品」准备的。

⑥ 签名过的 HAP 为什么不建议发？

调试 profile 绑定了本机板子的 UDID，别人装会报 not trusted app source；而且实测 API 22 字节码在 API 15 板子上启动崩溃。发出去只会让人误以为能用。

⑦ 如果 push 完发现真实 ai_config.json 被传上去了，第一件事做什么？

去模型平台轮换作废那把 API Key。删文件、删提交、甚至删仓库都救不回已经公开的凭据，只有作废才真正止损，之后再处理 Git 历史。
