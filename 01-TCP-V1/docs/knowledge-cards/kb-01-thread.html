线程与多线程

对应项目文件：server/test_client.py（单元 3 · 收发分离改造）

一、为什么这是重点

这个知识点不是课本带来的，而是我们亲手踩出来的。单元 3 你在现场看到：单线程版客户端 step1_test_client.py 连上车端后，屏幕上什么都没有；随手发一条指令，积压的几十帧 STATE 瞬间炸屏。这个现象背后的原理，正是面试里反复出现的"线程与阻塞"。

二、项目案例复盘：单线程为什么会"炸屏"

旧版客户端的主循环长这样：

while True:
    text = input("> ")            # ① 卡在这里等键盘
    sock.sendall(text.encode())   # ② 有输入才发送
    data = sock.recv(4096)        # ③ 有发送才回来收一次
    print(data)

三个致命点：

① 主线程堵在 input() 上。没人去调用 recv()，但服务端每 100ms 推一帧 STATE—— 这些数据没有消失，全堆在操作系统为这条连接维护的接收缓冲区里。

② "发一条才收一次"。recv 平时根本不工作；你发指令后它被唤醒，一次把积压的一坨全读出来——这就是"批量炸屏"。

③ 收和发互相拖累。想实时看位置？必须不停发指令才能"捞"到新帧——收发完全耦合。

三、多线程方案：收发分离

新版 test_client.py 的解法是给"听"和"说"各派一个人：

# 后台线程：专职收帧，收到立刻打印（daemon=True：主线程退出它自动跟着死）
t = threading.Thread(target=recv_loop, args=(sock,), daemon=True)
t.start()

# 主线程：只管读键盘发送
while True:
    text = input("> ")
    if text in ("quit", "exit"):
        break
    sock.sendall((text + "\n").encode("utf-8"))

效果：STATE 每 100ms 一帧实时滚动，指令随敲随发，互不影响。

线程间通信在这个文件里出现了三处，都是面试考点：

机制项目中的用法要点
共享变量（原子操作）received["n"] 收帧计数用 dict 包一层是因为简单赋值在 CPython 下原子够用；复杂读改写要加锁
Event（事件信号）stop = threading.Event()主线程 stop.set() 通知收线程"该下班了"，收线程每圈 stop.is_set() 检查
daemon 线程收帧线程设为 daemon主线程退出时不被收线程拖住；但 daemon 里别放"必须做完"的事

还有一个容易被忽略的细节：收线程拿到的是字节流，同样要按 \n 分帧再打印—— 多线程解决了"谁去收"，分帧解决"收到的算一条"（见 06 协议设计）。

四、核心概念梳理

1. 线程是什么

线程是操作系统调度的最小执行单位。一个进程至少有一个主线程；多线程 = 一个进程里同时存在多条执行路线， 共享同一份内存（全局变量、打开的 socket 都可以直接访问——这也是它通信方便又容易踩坑的原因）。

2. 为什么需要多线程：阻塞

input()、recv() 这类调用是阻塞式的——数据没来，整个线程停住等。 一个线程同一时刻只能"等一件事"。要"同时听和说"，要么开两个线程，要么用异步（见下）。

3. 本项目里其实用了两种并发方案

客户端 test_client.py服务端 car_server.py
方案多线程（threading）asyncio 协程（单线程事件循环）
并发单位操作系统线程协程（用户态"轻量线程"）
适用场景少量长期任务（就 2 条线程）大量并发连接（每连接一个协程，开销极小）
切换成本OS 内核切换，较重函数级切换，极轻
坑共享数据要考虑竞态协程里不能有阻塞调用（一个 time.sleep 卡死全部）
面试加分点：能同时说出这两种方案、各自的适用场景，并解释"为什么客户端只有两个长任务用线程就够， 服务端可能几十个连接更适合 asyncio"——说明你不是背概念，而是做过选型。

五、面试高频问答

Q1：进程和线程的区别？

A：进程是资源分配单位（独立内存空间），线程是调度执行单位（共享所属进程的内存）。 进程间通信要走 IPC（管道/共享内存/消息队列），线程间直接读写共享变量（需处理竞态）。 本项目单进程：主线程 + 收帧线程共享 received 计数和 socket。

Q2：什么是阻塞？什么是非阻塞/异步？

A：阻塞 = 调用后数据没就绪就一直挂着（input()、recv()）。 非阻塞 = 立刻返回"还没好"。异步 = 把"等"这件事交给事件循环，就绪后回调/唤醒你。 单线程炸屏就是阻塞的代价；asyncio 是异步的典型实现。

Q3：多线程之间怎么通信？

A：① 共享变量（注意竞态，需要锁或原子操作）；② threading.Event 等信号对象； ③ 队列 queue.Queue（生产者-消费者模式，线程安全）。 本项目用了前两种：计数用共享 dict，退出信号用 Event。

Q4：daemon 线程是什么？

A：setDaemon(True)/daemon=True 的线程是"守护线程"：主线程退出时它被直接终止， 不会阻止进程结束。适合"辅助性、随时可断"的任务——比如我们的收帧打印线程。

Q5：GIL 是什么？影响本项目吗？

A：CPython 的全局解释器锁——同一时刻只有一个线程在执行 Python 字节码。 但本项目收线程大部分时间阻塞在 socket I/O 上，等数据时锁会释放，所以多线程对 I/O 密集任务依然有效。 （GIL 主要卡的是纯 CPU 计算的多线程加速。）
