生活比喻

为什么"装软件"还分系统

把这件事想成给一台装了 Linux 的工控机装软件：

  • 板子 = 一台小电脑，出厂已经装好操作系统（OpenHarmony 7.0.0.33）。烧录是把整套系统镜像重新刷进去 —— 那只在系统坏了或要换版本时才做，现在完全不需要。
  • HAP = 这个系统认的安装包，相当于 .apk / .exe。hdc install 就是"双击安装包"。
  • 但安装包分"发行版"：给 Ubuntu 编的包不一定能在另一个发行版上跑。CarOH 是按 OpenHarmony（开源版）编的，CarFleet 是按 HarmonyOS（华为商用版，带一套专属 Kit）编的 —— 后者拿到板子上，系统会说"这个包我不认识"。
  • 签名 = 安装包上的公章。板子只认盖过章的包，所以必须用 CarOH-signed.hap，不能用 entry-default-unsigned.hap。
  • USB OTG 线 = 数据线。板子有两个 Type-C，只有靠近 HDMI 的那个是"设备口"；插错口或者用了只能充电的线，电脑这边根本看不见板子 —— 这正是现在的状态。
一句话记住：「烧系统」和「装 APP」是两件事；「装 APP」之前先确认「包是给哪个系统编的」；装完再确认「它要连的是哪台电脑上的哪个端口」。

三条真正可行的出路（按代价从大到小）

路线要做什么代价 / 前提
A 正统重编译装一个匹配板子的 OpenHarmony SDK（API 12/15），把 CarOH 的 compatibleSdkVersion 改成对应值，重新 assembleHap → 用现有证书重新签名 → hdc install本机目前只有 API 20 / 22 两套 SDK，需先补装；编译产物才能真正被 API 15 的 Ark 运行时加载

眼下已经在板子上跑起来的：com.example.smart_car_oh（API 12，之前课程装的智能车应用）。我已执行 aa start 成功，你在板上手动上滑解锁就能看到它。如果你要装的其实就是这个，那它早就装好了、不用再装。

顺带回答上一问：装到"真机 / 模拟器 / 这块板"能不能语音控车

目标打字控车网页语音按钮要做语音，正确的做法
手机真机（装 CarFleet）可用 灰的 页面 ai_chat.html:294 检查 window.isSecureContext；真机访问 http://<PC IP>:8000 是普通 HTTP → 按钮被写死禁用 ① module.json5 补 ohos.permission.MICROPHONE → ② 运行时申请 → ③ APP 原生 AudioCapturer 录音成 16k WAV → ④ POST 到已有 /ai/command 的 audio_b64；或用 Core Speech Kit 端侧出文字走 text 分支
DevEco 虚拟模拟器可用灰的 同样是非安全上下文；且 ArkWeb 默认拒绝网页 getUserMedia 官方文档：模拟器支持把电脑麦克风透传给 AudioCapturer（推荐 48kHz / 2ch / 16bit PCM）；Core Speech Kit 的模拟器支持随 DevEco 版本变化，官方仍建议真机验证
DAYU200（本页主角）CarOH 里没有文字 AI 入口不存在语音模块 CarOH 只有 TCP / 云端两种控车模式 板子只负责"采集声音"，AI 全放在 PC 后端：用 OpenHarmony 的 AudioCapturer 或 USB 麦录 16k WAV → base64 → POST http://<PC IP>:8000/ai/command。OpenHarmony 没有 HarmonyOS 的 Core Speech Kit，但也不需要——模型在云端
后端这一端早就准备好了。今天直接用静音 WAV 打过对照：带 audio_b64 → 400 没有识别到清晰的语音（说明已进 ASR 转写分支）；什么都不传 → 400 缺少 text 或 audio_b64。也就是说只差一段真实人声，任何设备只要能把声音送进这个接口，AI 解析、白名单校验、下发命令全都会照常工作。

想在这块板上用 V3 车队 / AI：不用装 HAP

因为 V3 的全部界面本来就是网页，只要板子上有浏览器、且和 PC 同一网段，直接打开：

http://<PC局域网IP>:8000/monitor/view    实时监控大屏
http://<PC局域网IP>:8000/admin/view      管理后台（admin / admin123）
http://<PC局域网IP>:8000/track/view      轨迹回放
http://<PC局域网IP>:8000/ai/view         AI 文字 / 语音控车

后端已用 app.run(host="0.0.0.0", port=8000) 监听，同网段可访问；PC 防火墙需放行 8000。先验证浏览器有没有：hdc shell bm dump -a 找 browser / web 相关 bundle。

这条路的额外好处：AI 模型调用、密钥、白名单、命令下发全在 PC 后端，板子只是个显示 + 输入终端，不需要给板子编任何新 HAP。

#现象原因 / 处理
1hdc list targets 里有 127.0.0.1:5555那是 DevEco 虚拟模拟器（emulator 6.0.0.130 / API 22），不是板子。接线前列表里只有它；接好 USB OTG 后会同时出现板子的随机序列号。务必用 -t <板子序列号> 指定目标，否则可能装到模拟器上

3想装 CarFleet 的 HAP 到板子订正：换成 OpenHarmony 官方调试签名 + 降版本声明后能装上去（实测 install bundle successfully）；但它是 runtimeOS: HarmonyOS / ark13.0.1.0 字节码，板子 API 15 运行时加载会 Cpp Crash。要真正运行必须用匹配板子的 SDK 重新编译源码
4拿 entry-default-unsigned.hap 去装未签名包会被拒；必须用 CarOH-signed.hap
59568293 check syscap failed包声明 minAPIVersion=20 且 rpcid.sc 要求 API 20 的全套系统能力；板子实测 API 15。不是包坏了，是系统与包版本不匹配 → 换匹配 SDK 重编译，或把板子刷到 7.0
6装好了但连不上 PC板子要插网线到同一路由器；hdc shell ifconfig eth0 查板子 IP，PC ipconfig 查 PC IP，先 ping 通再试；Windows 防火墙放行对应端口

11板子上语音按钮灰色 / 没反应网页 getUserMedia 要 HTTPS 或 localhost，局域网 HTTP 访问会被禁；OpenHarmony 也没有 Core Speech Kit。改用原生 AudioCapturer 录音 → POST /ai/command 的 audio_b64

13板子 APP 显示「后端不通」三查：PC 后端是否在跑（curl 127.0.0.1:8000/health）、APP 里 IP 是否是 PC 当前 IP（热点重连后会变）、两者能否互 ping。手机热点常做客户端隔离 → 用 hdc rport tcp:8000 tcp:8000 + APP 填 127.0.0.1:8000 绕开
