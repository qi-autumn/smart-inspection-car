常见坑

全部是这次实测踩到或提前挡掉的

接口裸 base64 会被拒

中转的 input_audio.data 要 URL 或 data:audio/wav;base64,…。直接塞裸 base64 → 400「The provided URL does not appear to be valid」。后端 transcribe() 已自动补 data URI。

接口没有 /audio/transcriptions

该中转返回 404，别照 OpenAI 的 Whisper 端点写。音频统一放进 chat/completions 的 input_audio。

数据模型把「3号车」输出成 "3"

实测 Function Calling 返回 device_id: "3"。normalize() 会自动补成 car_003 并用 resolve_device_id() 复核；编造的 car_099 直接整单拒绝。

数据静音被模型"编"成一段音乐

全模态模型面对无语音音频容易输出听感描述。转写层加了幻觉词过滤 + 必须含控车线索词的双重检查，否则返回「没有识别到清晰的语音」。

延迟深度思考默认开启

响应里有 reasoning_content，思考 token 也计费。配置里 enable_thinking: false，短指令实测 1.7~3.2 秒完成"解析 + 下发"。

安全AI 输出仍必须过白名单

工具 schema 里的 enum/min/max 只是建议；服务端 normalize() 与 build_move_paras() 又各验一遍。幻觉命令、越界速度、冻结设备都被拦。

协议「开三秒」不会自动停

现有 /command 没有时长字段。后端把 duration_ms 变成"等 3 秒再发下一条 STOP"，全程上限 10 秒、最多 8 步，并用 AI_LOCK 防止两个 AI 任务交错控车。

反馈别把模型的 say 当执行结果

页面上的「已下发 N 条命令」由每步真实返回值统计；任一步 502/403 就中止后续并如实说失败，不用模型自己写的"已完成"。

网页局域网 IP 打开时麦克风灰掉

http://192.168.x.x:8000 不是安全上下文。PC 用 127.0.0.1；手机/别的电脑访问要先按 HTTP 与 HTTPS 升级，或暂时只用文字输入。

音频webm/opus 要转 WAV

MediaRecorder 默认给 webm/opus，云 ASR 常要 wav/pcm。页面用 AudioContext 解码后重采样到 16k 单声道并手写 WAV 头，再 base64 上传。

APP模拟器只能玩文字模式

端侧语音识别需要真机与 ohos.permission.MICROPHONE；DevEco 虚拟手机没有真实麦克风。APP 内嵌 Web 也请用「AI 控车」按钮切页后先打字验收，并记得重新构建安装。

密钥别让 key 进仓库 / 文档

配置支持 V3_AI_API_KEY 等环境变量覆盖；.gitignore 已忽略配置文件与已有明文 AK/SK 的 cloud_config.json。地域化 API Key 不通用，换中转要连地址一起改。
