这里的「外接模拟器」外接的是一台虚拟手机（DevEco 里的鸿蒙模拟器），也就是多接一个客户端；小车模拟器、业务后端、华为云那套东西一个都不用改。虚拟手机通过专用地址 10.0.2.2:8000 找到宿主机 PC 上的后端，跟真机、跟 PC 浏览器是平级的第三个观看／操作入口。

1

一句话结论

先背这一句
先在 PC 上把「小车模拟器 + 业务后端 8000」跑起来，再用 DevEco 打开 CarFleet 工程、启动手机模拟器、点运行装好 APP，最后在 APP 选车页把地址填 10.0.2.2、端口 8000，点「连接」就完成了。 10.0.2.2 是「模拟器里的手机看宿主机 PC」的专用别名，不是 PC 的局域网 IP，也不是 127.0.0.1。APP 从头到尾只跟后端 :8000 说话，不连华为云、不连小车。
先澄清一个最容易混的点：这次「外接」的是虚拟手机（跑 APP 的客户端），不是再接一台小车模拟器。小车模拟器仍然是 PC 上那几个黑窗。接进来的手机只是让你可以用 APP 的界面看车队、摇杆控车、看轨迹、进管理后台——和 PC 浏览器打开大屏是同一层东西。

PC 上必须活着

① 小车模拟器黑窗（至少一台）② python server\app.py 的 8000 后端。少一个，APP 连上了也是空列表／全离线。

DevEco 里要做的事

打开 CarFleet 工程 → Sync/自动签名 → Device Manager 启动 phone 模拟器 → Run 安装 HAP。

APP 里只填两个数

地址 10.0.2.2、端口 8000，点「连接」。看到「车队共 N 台车」就是通了。

2

生活比喻：给虚拟手机办一张「内线电话卡」

不用记术语

把网络想成一栋办公楼，就不容易把三种地址搞混了。

PC 是公司总机室：后端 :8000 是总机接线员，小车和账本都在楼里。PC 浏览器是总机室里的人，拿起内线打给自己，拨 127.0.0.1（"我就在这儿"）就行。

DevEco 手机模拟器是一台放在楼里、但有自己的独立电话系统的虚拟手机。它拨 127.0.0.1 会打给自己（手机里的空房子），所以系统专门给它一条内线：拨 10.0.2.2 就能通到宿主 PC 的总机。这条内线是模拟器软件自动铺好的，不用你配路由。

真手机在楼外，得走外线：要查 PC 的局域网 IP（如 192.168.1.23）拨过去，还要保证同一个 WiFi、防火墙放行。

所以「外接模拟器」的全部难点只有一个：让这台虚拟手机拨对号码。代码、协议、云端配置全都不用动——APP 里写死的就是 http://${host}:${port}/...，填什么地址它就拨给谁。

涉及的文件与接口：APP 拨出去的四个号码

查手册用

全是 HTTP 短连接（APP 没接 WebSocket）。目标都是 http://10.0.2.2:8000 这一台后端。

时机接口频率APP 拿它干嘛 / 代码位置
点「连接」GET /fleet/status一次探活取整队 cars[] 渲染列表；失败就报错。FleetClient.ets:55、Index.ets:192~197
连上之后GET /fleet/status每 800ms轮询刷新地图／状态面板；连续 3 次失败自动断开。FleetClient.ets:174 / 208
推摇杆 / 停车POST /command按需发 {device_id, cmd:"MOVE", angle, speed} 或 STOP；连接超时 5s、读超时 8s。FleetClient.ets:123 / 132 / 213
切到轨迹视图GET /track?device_id=打开视图时从后端 SQLite 取历史点画折线。FleetClient.ets:140
点右上角「管理后台 ›」GET /admin/view打开视图时ArkTS Web 组件加载 http://${host}:${port}/admin/view，跟浏览器打开的是同一个页面。Index.ets:1053

一次摇杆推动，在 APP 这条线上怎么走

APP（DevEco 模拟器） ──HTTP POST /command──▶ PC 后端 :8000
      └─ 10.0.2.2 只是"宿主机"的别名，实际走的是模拟器虚拟网卡 → 宿主 PC

PC 后端 ──HTTPS SDK CreateCommand──▶ 华为云 IoTDA ──MQTT 8883──▶ 小车模拟器黑窗
小车 ──5s 上报属性──▶ 设备影子 ──后端每 2s 拉一次──▶ STATE_CACHE
      └─（模拟阶段还有 10Hz 本地旁路让画面更顺）

APP ──每 800ms GET /fleet/status──▶ 后端 STATE_CACHE ──▶ ArkTS Canvas 重画小车

所以 APP 画面天生比网页大屏慢一档：网页有 WebSocket 主动推，APP 只有 800ms 轮询。这不是外接模拟器造成的问题，是架构本来就如此（详见 长连接与短连接）。

常见坑：连不上时按这张表从上往下查

排错顺序
现象原因怎么处理
APP 点连接转圈后报网络错误 / 超时虚拟手机访问不到宿主机：后端没起、被旧进程占端口、或 Windows 防火墙拦了 8000 入站先做第 2 步的 curl；PC 通而手机不通 → 放行 8000 入站规则。FleetClient.ets:60 的 connectTimeout 只有 5s，超时很快，别反复狂点。
把 127.0.0.1 填进了 APP在手机里这个地址指的是手机自己DevEco 模拟器填 10.0.2.2；真机填 PC 局域网 IP；PC 浏览器才用 127.0.0.1。Index.ets:677 的输入框提示就是这么写的。
换了网络 / 改过地址，还是连旧地址preferences('fleet_bind') 记住了上次的 host在选车页手动改回并重新点「连接」（savePrefs 会覆盖）；实在不行清除 APP 数据重置。Index.ets:123~148
连上了，但车全是「离线」小车模拟器黑窗没开 / MQTT 掉线 / 云端密钥错；不是 APP 的问题看黑窗有没有 设备上线成功；去管理后台点「上线」；curl http://127.0.0.1:8000/health 看 online 数。
连上了，列表是空的后端 devices.json 没设备，或首轮轮询还没完成等 2 秒再点连接；确认注册表非空。
用着用着自动「断开连接」连续 3 次轮询失败触发 MAX_FAIL查后端窗口是否被关、PC 是否休眠断网、8000 是否被旧进程抢走。FleetClient.ets:17 / 208
Run 时 SignHap 失败 / bundleName 报错自动签名还没配置好DevEco 登录华为账号后 Sync，让工具自动重签；不要手动改 AppScope/app.json5 的 com.example.carfleet。
Device Manager 里找不到能跑的设备module.json5 只声明了 deviceTypes: ["phone"]创建／选择 Phone 模拟器，SDK 版本对齐 6.0.2(22)。
内嵌管理后台按钮点了没反应Web 组件吞掉原生 confirm/alert后台已改自绘弹窗；若仍异常，先用 PC 浏览器打开 /admin/view 对比，确认是页面还是容器问题。
8000 上出现两个后端进程旧 Python 进程没杀干净，请求被随机抢走netstat -ano | findstr :8000 找 PID → taskkill /F /PID <pid>，再重启后端。
APP 画面不如网页大屏流畅APP 是 800ms HTTP 轮询，网页是 WebSocket 主动推 + 10Hz 本地旁路架构使然，不是配置错。要一样丝滑需把 APP 改成 WebSocket 并在 DevEco 重新构建。
将来后端升级成 HTTPS 后 APP 全挂APP 里 4 处 URL 写死了 http://改 FleetClient.ets:58 / 90 / 144 与 Index.ets:1053，并处理自签证书信任；方案见 HTTP 与 HTTPS。

B. 一条命令定位"卡在哪一段"

REM ① 后端活着吗？（本机）
curl http://127.0.0.1:8000/health

REM ② 有车在线吗？
curl http://127.0.0.1:8000/fleet/status

REM ③ 端口只被一个进程监听吗？
netstat -ano | findstr :8000

REM ④ 小车本地状态在动吗？（旁路，验证模拟器本体）
curl http://127.0.0.1:8081/state

REM ⑤ 手动发一条命令（APP 摇杆走的就是这个接口）
curl -X POST http://127.0.0.1:8000/command -H "Content-Type: application/json" -d "{\"device_id\":\"YOUR_PRODUCT_ID_car_001\",\"cmd\":\"MOVE\",\"angle\":30,\"speed\":60}"

① 不通 → 后端没起；② online=0 → 小车没上线；③ 多个 PID → 杀旧进程；④ 坐标不动 → 小车模拟器死了；⑤ 返回 ok:true 但车不动 → 去黑窗看有没有收到 [命令] move。APP 连不上时，先用这五条把问题锁在 PC 侧，再去怪 DevEco。

2. 不用改任何源码。这次只是"运行已有 APP 工程 + 在界面填地址"；默认 host 就是 10.0.2.2。

3. 因为外接的是客户端（虚拟手机）。小车模拟器、后端、华为云都在 PC／云上，APP 只跟 :8000 说话。

4. 先查 PC 侧：后端是否活着、防火墙是否放行 8000、端口是否被旧进程抢占；/fleet/status 的 cars[] 是否为空。
