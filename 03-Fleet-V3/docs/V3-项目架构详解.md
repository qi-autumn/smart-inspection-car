## 1. 项目定位

多台智能巡检车通过华为云 IoTDA（设备接入服务）组网，实现：

- **车队管理**：注册/注销车辆、上线/下线、冻结、云端对账（管理后台）
- **实时监控**：网页大屏 + APP 实时地图，全队车辆位置/朝向/电量可视化
- **矢量控车**：摇杆（网页）+ 摇杆（APP）下发 MOVE(vx,vy) 矢量命令
- **轨迹回放**：位置历史落 SQLite，按时间窗回放
- **多端一致**：网页与 APP 只消费同一个业务后端，不直连云端

```
│  web/fleet_console.html          CarFleet APP (HarmonyOS)    │

│ 业务后端层  server/app.py (Flask :8000)                      │
│   ├ STATE_CACHE 全系统唯一状态源（内存，2s 轮询云端刷新）       │
│   ├ 乐观回显：命令受理即改缓存并立即推 WS                      │
│   ├ /admin/*：注册/删除/冻结/上下线/对账（唯一动基础设施的模块）│
│   └ track_store.py + SQLite(WAL) 轨迹库                      │
└───────┬─────────────────────────────────────▲───────────────┘
        │ IoTDA V5 SDK (AK/SK)                │ 设备影子/命令
┌───────▼─────────────────────────────────────┴───────────────┐
│ 华为云 IoTDA (cn-north-4, 实例 fa2da76a-...)                  │
│   MQTT 接入(8883/TLS) · 设备影子 · 命令队列(car_control)       │
└───────▲─────────────────────────────────────────────────────┘
        │ MQTT 上报 + 订阅命令
┌───────┴─────────────────────────────────────────────────────┐
│ 设备模拟层  device/car_mqtt_client.py ×N 实例（每车一个进程）   │
│   CarSim 20Hz 运动积分 · 5s/60s/事件 上报 · 本地调试 /state    │
└─────────────────────────────────────────────────────────────┘
```

**核心架构决策：STATE_CACHE 是全系统唯一状态源。** 任何客户端都不碰云端，云端的变化只能通过后端轮询进入系统。

## 4. 接口详解

### 4.1 设备 ↔ 云端（MQTT，模拟器与将来真车共用的协议）

| 项 | 值 |
|---|---|
| 接入地址 | iot-mqtts.cn-north-4.myhuaweicloud.com:8883 (TLS) |
| ClientID/用户名/密码 | IoTDA 平台为每台设备生成的三元组（devices.json 存 secret） |
| 上行 topic | `$oc/devices/{device_id}/sys/properties/report` |
| 下行 topic（订阅） | `$oc/devices/{device_id}/sys/commands/#`（`request_id=` 从 topic 提取用于回执） |

**物模型两个服务：**

- `car_status`（属性上报，只读）：
  ```json
  { "services": [{ "service_id": "car_status",
      "properties": { "x": 10.2, "y": 5.0, "theta": 90.0,
                      "speed": 60.0, "battery": 98.5 } }] }
  ```
  坐标系：x 向东、y 向北；theta=朝向角（0=正北，顺时针增大）。

- `car_control`（命令，云端下发）：
  - `move` 参数 `{"vx": 0.5, "vy": 1.0}` —— 车体坐标系的瞬时速度矢量（vx 右、vy 前）
  - `stop` 无参数
  - 注意：命令挂 `car_control`，属性挂 `car_status`，两者不可混。

**上报节奏（路线图硬约束，保护 IoTDA 免费单元每日约 1 万条配额）：**

| 场景 | 间隔 |
|---|---|
| 行驶中（speed>0.01） | 5 s |
| 静止 | 60 s |
| **命令执行后** | 立即事件补报（限流 2 s，防摇杆连发打爆配额） |

### 4.2 后端 ↔ 云端（IoTDA V5 Python SDK，AK/SK 鉴权）

| SDK 调用 | 用途 | 备注/坑 |
|---|---|---|
| `ShowDevice` | 查单台在线状态 | **ListDevices 的 device_id 过滤参数不生效**，查状态必须逐台 ShowDevice（响应 status 平铺在 resp.status） |
| `ShowDeviceShadow` | 拉设备影子 | 影子属性在 `resp.shadow[].reported.properties`，数值是 Decimal |
| `CreateCommand` | 下发 move/stop | 命令体类是 `DeviceCommandRequest`（不是文档的 CommandBody） |
| `AddDevice` / `DeleteDevice` | 注册/注销设备 | 注册前先 DeleteDevice 清残留，否则报"已存在" |
| `ListDevices` | 云端对账 | **limit 上限 50**（传 100 报 400），按 product_id 客户端过滤 |

### 4.3 后端对外接口（REST :8000，响应统一包络 `{ok, error, ...data}`）

**查询类：**

| 方法/路径 | 参数 | 返回 |
|---|---|---|
| GET `/health` | — | 后端存活 |
| GET `/devices` | — | 注册表全部车辆（含 color/name/frozen） |
| GET `/status` | device_id | 单车状态（缓存） |
| GET `/fleet/status` | — | 全队状态数组，APP 800ms 轮询用；每项 `{device_id,name,color,online,x,y,heading,speed,battery,time}` |
| GET `/track` | device_id(必填), from, to（缺省最近24h；支持 Unix 秒或 `YYYY-MM-DD HH:MM[:SS]`） | 时间升序轨迹点 `[{x,y,theta,speed,battery,t}]`，t 为 `YYYY-MM-DD HH:MM:SS` 字符串 |
| GET `/audit/recent` | — | 最近审计 |

**控制类：**

| 方法/路径 | 请求体 | 语义 |
|---|---|---|
| POST `/command` | `{device_id, cmd, speed, angle}` | cmd ∈ FORWARD/BACK/LEFT/RIGHT/STOP/MOVE。MOVE 需 angle(0-360)+speed(0-100)，后端换算 `vx=sin(a)·v/100, vy=cos(a)·v/100`。**当前语义=云平台已受理**（拉模式收不到设备回执，推送通道是后续升级项）。受理成功后触发乐观回显 |

**WebSocket `/ws`**（监控大屏用）：

```json
{ "type": "fleet_state", "ts": 1699000000,
  "cars": [ { "device_id": "..._car_001", "name": "1号巡检车", "color": "#3aa55d",
              "online": true, "x": 10.2, "y": 5.0, "heading": 90.0,
              "speed": 60.0, "battery": 98.5, "time": "..." }, ... ] }
```
推送节奏：**事件驱动**（命令受理立即推一帧）+ 0.5s 兜底周期。

**管理类（鉴权头 `X-Auth-Token`，登录 `POST /admin/login` 体 `{username, password}`）：**

| 方法/路径 | 作用 |
|---|---|
| POST `/admin/login` | 登录发 token（内存态，重启失效） |
| GET `/admin/overview` | 总览统计 |
| GET `/admin/devices` | 注册表设备 + 实时状态 |
| POST `/admin/devices` | 注册新车（先 DeleteDevice 清云端残留→AddDevice→写 devices.json，分配颜色/出生点/调试端口，返回一次性密钥） |
| POST `/admin/devices/<did>/freeze` | 冻结/解冻（冻结后 /command 一律 403） |
| DELETE `/admin/devices/<did>`（body `{confirm:true}`） | 注销：停模拟器→云端 DeleteDevice→移出注册表；车队至少保留一台 |
| GET `/admin/cloud/devices` | **云端对账**：ListDevices vs 注册表，标注"两边一致/云端残留/本地多出" |
| DELETE `/admin/cloud/<did>` | 仅删除云端残留记录 |
| POST `/admin/devices/<did>/start` \| `/stop` | **一键上线/下线**：后端按命令行特征（car_mqtt_client.py + --device）查找/拉起/终止本机模拟器进程 |
| GET `/admin/commands` | 命令历史 |

**展示页路由**：`/monitor/view` `/admin/view` `/track/view` `/console/view`。

### 4.4 后端内部接口（模块间）

| 调用方 → 被调方 | 接口 |
|---|---|
| poll_loop → cloud_show_status/shadow | 每 2s 轮询全部设备在线状态+影子 → 写 STATE_CACHE（CACHE_LOCK 保护） |
| /command → `_echo_command_state` | 命令受理即把预期 heading/speed 写入缓存 + 置 WS_DIRTY 立即广播 |
| poll_loop ← ECHO_PENDING | 回显守卫：回显后 4s 内旧影子不得覆盖缓存；真实回报（值变化）即清除 |
| poll_loop → track_store.insert_point | 仅真实影子观测、且与上次相比有变化才插行（**乐观回显值不入轨迹库**） |
| /admin devices start/stop → subprocess | 以 CREATE_NEW_CONSOLE 拉起模拟器；stop 时 PowerShell 按 `car_mqtt_client.py --device <node>` 特征 taskkill 全部实例 |
| fleet_state_message → STATE_CACHE + DEV_META | 缓存快照 + 注册表名称/颜色合成广播帧 |

### 4.5 APP 端接口（CarFleet / FleetClient.ets）

| 方法 | 行为 |
|---|---|
| `startPolling()` | 每 800ms GET `/fleet/status`，刷新车队页卡片与操控页地图 |
| `bind(deviceId)` | 免重连切车：仅切换本地 selectedId，操控页地图与摇杆随之指向新车 |
| `sendCommand(cmd/angle/speed)` | POST `/command` |
| `fetchTrack(deviceId, from, to)` | GET `/track`，Canvas 回放（t 字段需 `Date.parse(replace(' ','T'))` 转 ms） |
| 管理后台视图 | ArkTS Web 组件内嵌 `http://host:8000/admin/view`（javaScriptAccess + domStorageAccess） |

### 4.6 页面端内部约定（流畅度核心：分段航位推算）

数据链路固有节奏：**模拟器 5s 上报 → 后端 2s 轮询影子 → WS 0.5s 兜底广播**。为让画面流畅，monitor.html 在客户端做两级处理：

1. **乐观回显**（后端推）与**真实影子回报**严格区分：
   - x/y 变化 = 真实位置修复 → 外推起点对齐最新观测
   - 仅 heading/speed 变化 = 命令回显 → **起点沿旧方向推进到当前时刻再换向**（连续折线，与真车运动一致），命令→画面可见实测约 **0.33s**
2. 指数平滑趋近 + 航向最短弧插值；8s 无新观测则 3s 内减速滑行到停（防漂移）
3. 对比开关：`/monitor/view?plain=1` = 纯观测模式（不做预测，5s 一跳的诚实显示）

## 5. 关键数据流

### 5.1 控制命令双通道（摇杆 → 车动 → 画面动）

```
快通道（≈0.3s，负责跟手感）：
  摇杆 → POST /command → CreateCommand 受理
       → 乐观回显写缓存 → 立即 WS 帧 → 页面外推转向

慢通道（≈2s，负责真实性）：
  CreateCommand → MQTT 下发 → 模拟器 on_message 执行（20Hz 积分生效）
       → 事件补报属性 → 影子更新 → 后端 2s 轮询 → 校准缓存
       → （真实回报清除回显守卫，轨迹落库）
```

### 5.2 状态上行主干

```
CarSim 20Hz 快照 → 上报循环(5s/60s/命令后≤2s) → MQTT car_status
  → 设备影子 → poll_loop(2s) → STATE_CACHE
     ├→ /ws 广播（大屏）
     ├→ /fleet/status（APP 800ms 轮询）
     └→ track_store（变化才插行）→ /track（回放）
```

### 5.3 管理操作流

- **注册车**：管理后台 → AddDevice（先清残留）→ devices.json 增行（端口/颜色/出生点）→ 返回密钥
- **上线**：点按钮 → 后端拉起模拟器进程 → MQTT 连上 → ~3s 后云端 ONLINE → 全端可见
- **下线**：点按钮 → 后端按命令行特征杀进程 → 云端判离线
- **对账**：ListDevices（limit≤50）对比注册表 → 残留可单独清 / 本地多出提示
- **冻结**：devices.json frozen 位 → /command 403，设备本身不受影响

## 8. 约束与已知坑（踩过的）

1. **IoTDA 配额**：免费单元约 1 万条/日 → 上报节奏 5s/60s 是硬约束，勿调快
2. ListDevices 过滤参数不生效 → 查状态逐台 ShowDevice；limit≤50
3. 影子数值是 Decimal、命令体类是 DeviceCommandRequest（SDK 与文档的差异）
4. 注册前云端可能有残留（中断/控制台直建）→ 必须先 DeleteDevice
5. APP Web 组件不弹原生 confirm/alert → admin.html 全部改自绘弹窗
6. 模拟器多实例互踢 → 启动前检查调试端口占用；杀进程按命令行特征匹配（后端重启后也能杀外部进程）
7. 黑窗=模拟器本体，关窗=下线，只能最小化
8. 拉模式下 /command 语义是"云平台已受理"，设备执行回执需推送通道（AMQP/应用侧推送）后升级
9. 用户编辑器经常不保存文件就运行（App 端改动后需确认保存再构建）

## 9. 第⑧步真车接入指引

**只换最底层，云端与上层零改动**：真车固件实现与模拟器完全相同的 MQTT 协议——

1. TLS 连 8883，用平台三元组（设备注册时下发）
2. 按 car_status 物模型 5s 上报 x/y/theta/speed/battery
3. 订阅 `$oc/devices/{id}/sys/commands/#`，处理 car_control 服务的 move(vx,vy)/stop，收到即执行
4. （可选）命令执行后立即补报一次属性，获得与模拟器相同的 ~1s 命令可见性

升级方向：应用侧改用 AMQP/推送订阅替代 2s 轮询，命令可等设备真实回执（协议 §4.3 的 20s 回执语义届时补全）。
