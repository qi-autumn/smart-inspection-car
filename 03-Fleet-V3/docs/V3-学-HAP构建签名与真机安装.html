把 DevEco 里的代码装进设备：构建 → 签名 → 安装（不是"烧录"）

先把词说准：APP 开发里没有"烧录"这一步，正确说法是把 ArkTS 源码编译成 HAP 安装包 → 用调试证书签名 → 通过 DevEco 的 Run 或 hdc 安装到设备。"烧录／刷机"是给开发板写整套系统镜像（比如课程第二阶段给 DAYU200 烧 OpenHarmony），那是另一回事。

1

一句话结论

先背这一句
代码不是"烧"进手机的，是打包成 HAP → 签名 → 安装。装到 DevEco 的虚拟手机模拟器，点一下 Run ▶ 就已经全自动做完了；装到实体真机，则必须先做一次 DevEco 自动签名（登录华为账号、把真机 UDID 登记进调试 Profile），再选真机设备点 Run。 而且 APP 装进哪个设备，和它连哪台后端是两件事：虚拟手机填 10.0.2.2:8000，实体真机要填 PC 局域网 IP:8000。
刚核对到的实际状态（很重要）：你现在的 CarFleet/build-profile.json5 里 signingConfigs: [] 是空的，构建目录里只有 entry-default-unsigned.hap（未签名包，11-08 09:21 生成）和一份 11-07 的旧产物。所以现在直接把 HAP 拿到真机安装一定失败——先做第 5 节的"自动签名"，让 DevEco 生成带设备绑定的签名包。

虚拟手机模拟器

DevEco 内部的虚拟设备。Run 会自动构建+安装，无需 UDID、无需数据线；地址用 10.0.2.2。

实体真机

USB 连电脑、开开发者选项、自动签名登记 UDID、Run 选真机；地址用 PC 局域网 IP。

预览器 Previewer

只在 IDE 里画 UI，不是设备，不能装 HAP、不能联网，别和前两者混。

2

生活比喻：装 APP 是"搬一户人家"，烧录是"重盖整栋楼"

不用记术语

烧录镜像＝把整栋楼的墙体、水电、电梯全部换掉（给开发板写操作系统）。课程里给 DAYU200 刷 OpenHarmony 就是这种活，用烧录工具把 .img 写进存储。

装 HAP＝楼已经盖好、系统已经跑着，只是往某个房间搬进一户新住户。DevEco 把你的 ArkTS 代码、图片、配置压缩成一个 .hap 包（相当于打包好的行李），hdc install 或点 Run 就是"搬进去"。

签名＝物业开的入住许可证：证明这个包是谁做的、允许住进哪几栋楼。调试签名会写死一串 UDID（设备身份证号），所以"这台手机签出来的包"换个手机就装不上——这是真机调试最常踩的坑。

一句话记住差别：烧录改的是"系统"，装 HAP 改的是"系统里的一个应用"。CarFleet 是应用，所以只需要后者。

4

涉及的文件与接口：HAP 里装了什么、签名要哪三样

查手册用

HAP 包内部（就是个 zip）

用压缩软件打开 entry-default-unsigned.hap 能看到：

  • module.json —— 模块配置、权限、Ability 声明
  • ets/modules.abc —— ArkTS 编译后的字节码（不是 .ets 源码）
  • resources.index + resources/base/... —— 图片、字符串、页面路由
  • pack.info / pkgContextInfo.json —— 打包与签名元信息

所以"把代码装进手机"装的是编译结果，手机里看不到你的 .ets 源文件。

调试签名三件套

文件是什么
.p12密钥库（私钥），用来给包盖章
.cer数字证书，证明"谁盖的章"
.p7bProvision Profile：允许装到哪些 UDID、允许哪些权限、包名是什么

自动签名只用于调试，不能用于上架应用市场。换一台真机，必须把新 UDID 加进 Profile 再重新签名。

常用命令 / 菜单对照

动作推荐方式替代命令
编译DevEco 点 Run（自动编译）Build > Build Hap(s)/APP(s) > Build Hap(s)
签名File > Project Structure > Signing Configs > Automatically generate signature手动准备 p12/cer/p7b 并写进 signingConfigs（进阶，不推荐新手）
看设备DevEco 顶部设备下拉框hdc list targets
安装选好设备点 Run 'entry' ▶（构建+签名+安装一条龙）hdc install -r <签名后的.hap>（-r 覆盖安装保留数据）
抓日志DevEco 底部 HiLog 窗口hdc hilog
卸载 / 覆盖策略Run > Edit Configurations 勾 Keep Application Data默认"先卸载再装"会清掉 APP 记住的 host／绑定车号
强烈建议用 Run，不要手动拿 HAP 去 hdc install。手动导出的包常常缺设备绑定信息，真机会报 INSTALL_FAILED_TEST_ONLY；DevEco 在点 Run 时会额外处理签名与安装参数。

1
确认目标设备能被 DevEco 看见两条路线从这里分叉
A 虚拟模拟器：Tools > Device Manager 启动 Phone 模拟器，等开机到桌面。
B 真机：手机 设置 > 关于手机 连点版本号 7 次打开开发者选项 → 打开 USB 调试 和 USB 安装（通过 USB 允许安装应用）→ 数据线连接 → 手机上点"允许 USB 调试"授权。 
REM 在 DevEco 底部 Terminal 里执行（hdc 不在系统 PATH 时就用这里）
hdc list targets
验收：命令列出一个设备 ID；DevEco 顶部设备下拉框里也能选到它。列表为空 = 线/驱动/授权没通，别往下走。
2
做一次 DevEco 自动签名（真机必需；当前工程正好缺这步）最关键的一步
File > Project Structure > Project > Signing Configs → 勾选 Automatically generate signature → 登录华为开发者账号（需实名认证）→ 工具自动申请调试证书，并把当前连接真机的 UDID 登记进 Profile → OK 保存 → Sync / Clean Project。
验收：build-profile.json5 里 signingConfigs 不再是空数组，出现 storeFile / profile / certpath 等字段；用户目录 ~/.ohos/config/ 下生成 .p12/.cer/.p7b。包名必须与 com.example.carfleet 一致，不一致就让工具重新自动签名，别手改 bundleName。

虚拟模拟器通常也走同一套签名配置，做完一次两条路线都能用；如果只跑模拟器仍报签名错误，同样勾一次自动签名即可。

3
选设备，点 Run 'entry' ▶构建 + 签名 + 安装一次完成
在 DevEco 顶部设备下拉框选择 Phone 模拟器 或 你的真机，点绿色 ▶。DevEco 会依次：编译 ArkTS → 生成 HAP → 用刚才的签名材料盖章 → hdc install → 自动拉起 APP。
验收：Build 窗口出现 Build successful / Install successful；设备屏幕出现 CarFleet · 智能巡检车队 选车页。构建产物里出现签名包（entry-default-signed.hap 或 Run 控制台打印的路径）。
若想手动装：hdc install -r <签名后的.hap>。一定要用 IDE 自动签名输出的调试包；拿 entry-default-unsigned.hap 或未绑定 UDID 的包去装，会报 INSTALL_FAILED_TEST_ONLY / 签名校验失败。
4
按设备类型改 APP 里的后端地址这一步最容易漏
A 虚拟模拟器：填 10.0.2.2 : 8000（工程默认值，通常不用改）。
B 实体真机：用 ipconfig 查 PC 的 IPv4（如 192.168.1.23）填进去，端口 8000；手机和 PC 必须同一个 WiFi。 
ipconfig | findstr /i "IPv4"
REM 真机还要放行 PC 的 8000 入站（管理员 PowerShell）
netsh advfirewall firewall add rule name="V3 Flask 8000" dir=in action=allow protocol=TCP localport=8000
验收：点「连接」后 APP 日志出现 已连接后端，车队共 4 台车（在线 4）。真机里绝对不能填 10.0.2.2，那是模拟器专用别名。
5
验证控制闭环，确认装进去的是"活"的 APP三处同时看
点一台车 → 推摇杆。APP 发 POST /command，后端下发到云，云 MQTT 推给小车。
验收：① 小车黑窗打印 [命令] move vx=... vy=...；② PC 浏览器 127.0.0.1:8000/monitor/view 里同一台车在动；③ 手机上坐标每 800ms 刷新。三处对上 = 源码真的跑在设备里了。
6
改代码之后的正确姿势不用"重新烧录"
改了 .ets 就再点一次 Run ▶，DevEco 会增量编译并覆盖安装。想保留 APP 记住的 host／绑定车号，在 Run > Edit Configurations 勾 Keep Application Data（等价 hdc install -r）；默认"先卸载再装"会清掉这些记忆。
验收：设备上的界面换成新版本；日志里出现新的行为。换一台真机时，要把它自己的 UDID 加进调试 Profile 再重新签名，否则装不上。

常见坑：按现象查

排错顺序
现象原因怎么处理
装包报 INSTALL_FAILED_TEST_ONLY / 签名校验失败拿的是 unsigned.hap，或手动导出的包没有设备绑定信息用 DevEco 自动签名后直接 Run；手动装只能用 IDE 输出的签名调试包，加 -r。
自动签名按钮灰着 / 一直失败没登录华为开发者账号、未实名认证，或包名与 Profile 不一致在 Signing Configs 里点 Sign In 登录；让工具重新生成，不要手改 app.json5 的 bundleName。
这台手机装得上，换台手机就装不上调试 Profile 的 .p7b 绑定了 UDID 白名单把新手机的 UDID 加到调试设备列表，重新自动签名再装。调试签名本来就不是给多人分发的。
hdc list targets 为空USB 调试没开／没点授权弹窗／只开了 USB 调试没开"USB 安装"／数据线只充电逐项检查开发者选项，拔插一次重新授权；换一根能传数据的线。
DevEco 报 SDK / API 版本不匹配工程 targetSdkVersion 6.0.2(22)，真机系统 API 更高升级 DevEco 与 SDK，保证 SDK API ≥ 真机系统 API 版本。
真机上 APP 连不上后端填了 10.0.2.2；或 PC 防火墙拦 8000；或手机不在同一 WiFi真机填 PC 局域网 IP；放行 8000 入站；PC 侧先 curl 自检。
点 Run 之后 SignHap 失败签名配置缺失／bundleName 与证书不匹配（本项目踩过）回到第 2 步做自动签名并 Sync；不要直接改配置文件里的签名段。
命令行敲 hdc 提示找不到hdc 在 DevEco 自带的 SDK toolchains 里，没加 PATH用 DevEco 底部 Terminal 执行；或把 SDK 的 toolchains 目录加进系统 PATH。
APP 记住的旧地址又冒出来preferences('fleet_bind') 会保存 host/port/绑定车号选车页手动改正并点连接覆盖；或勾选 Keep Application Data 控制是否保留。
"预览器 Previewer 里能看，装到设备就没了"Previewer 只渲染 UI，不是设备、不装 HAP必须走 Device Manager 的模拟器或真机 + Run。
把 .hap 当成 APK 发给别人 / 想刷进开发板HarmonyOS 应用是 HAP；刷系统镜像是另一套工具与流程装 APP 用 hdc/Run；给 DAYU200 烧 OpenHarmony 镜像是设备开发，不属于本流程。
把 .p12 私钥提交到代码仓库调试密钥属于私有凭据放到用户目录、加入 .gitignore；发布上架需另外申请正式证书，自动签名仅供调试。

先做再翻答案

A. 五道理解题（点选项马上判分）

答对 0 / 5

B. 一条命令定位"卡在哪一段"

REM ① 设备被认出来了吗（DevEco Terminal）
hdc list targets

REM ② 后端活着吗（PC 本机）
curl http://127.0.0.1:8000/health

REM ③ 有车在线吗
curl http://127.0.0.1:8000/fleet/status

REM ④ 构建产物是不是签名包（应出现 signed 字样，而不是只有 unsigned）
dir /s E:\Harmony\Project\CarFleet\entry\build\default\outputs\default\*.hap

REM ⑤ 手动覆盖安装（仅在拿到 IDE 输出的签名调试包时使用）
hdc install -r E:\Harmony\Project\CarFleet\entry\build\default\outputs\default\entry-default-signed.hap

① 空 → 线/授权/驱动；② 不通 → 后端没起；③ online=0 → 小车没上线；④ 只有 unsigned → 还没做自动签名；⑤ 失败 → 别硬装，回 DevEco 点 Run。

参考答案（做完再展开）

1. 编译成 HAP → 调试签名 → 安装（Run 或 hdc install）。"烧录"指写系统镜像，是设备开发，不是 APP 开发。

2. 因为 build-profile.json5 的 signingConfigs 为空，构建只产出了 unsigned.hap；真机要求签名，且调试 Profile 要绑定该机 UDID。

3. 虚拟模拟器用 10.0.2.2（宿主机别名）；真机用 PC 的局域网 IP，并且要同一 WiFi + 防火墙放行 8000。

4. 优先用 DevEco 的 Run，它一条龙完成构建、签名、安装并处理调试参数；手动拿包容易因缺设备绑定报 INSTALL_FAILED_TEST_ONLY。

5. 不能。调试签名的 .p7b 绑定 UDID 白名单，必须把新设备登记进去重新签名；而且调试签名不能用于上架发布。
