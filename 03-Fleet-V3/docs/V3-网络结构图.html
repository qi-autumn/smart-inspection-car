轨迹回放要不要算一个独立的"端"？—— 不要

结论：不单独算一端，网络结构图里它已经是客户端层的一个视图（图中已画出）。理由：

1. 它没有自己的进程、端口和网络连接。所谓"端"在网络层面 = 一个独立的网络节点（有自己的 IP/端口/连接）。轨迹回放只是浏览器里的一个网页 track_demo.html（或 APP 里的一个页面），和监控大屏连的是同一个后端的同一个 8000 端口，只是调用的接口不同（它调 GET /track，大屏调 GET /fleet/status 和 WebSocket）。

2. 数据来源也不是独立的。轨迹数据是后端 poll_loop 在抄状态时顺手写进 SQLite 的支线，不存在"轨迹服务器"这种东西。谁想看轨迹，谁就是又一个普通客户端。

3. 类比：轨迹回放之于本系统，就像"查账单页面"之于银行 App——是同一个银行服务器上的另一个查询界面，不是一个新机构。

所以网络结构图里正确的画法：把它画在"客户端层"内部作为第四个视图（APP 内是第三个页面视图），而不是画成第五个节点。本图已按此处理。
